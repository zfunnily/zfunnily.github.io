Windows 远程 Mac mini：iOS WebDAV 播放器开发实践

最近在开发 iOS 平台的 WebDAV 播放器，开发环境选择的是 Mac mini。但实际使用中，我的主力机仍然是 Windows，而且只有一个显示器。如何在不频繁切换设备、不额外增加硬件成本的前提下，高效地远程使用 Mac mini，就成了一个绕不开的问题。

这篇文章就结合我自己的实践，聊一聊 Windows 远程 Mac mini 的几种方案对比，以及我最终的选择。

一、真实使用场景

先说一下背景条件，这点非常重要：

  • iOS 开发必须依赖 macOS（Xcode、证书、真机调试）

  • Mac mini 放在角落，当“编译机 / 开发机”

  • Windows 是主力工作环境（写代码、查资料、沟通）

  • 只有 一个显示器，不希望频繁插拔

  • 希望：

    • 延迟低
    • 足够稳定
    • 最好能支持外网访问

在这个前提下，我测试了三种常见方案。

二、方案一：RealVNC

特点：

  • 老牌远程桌面工具
  • 支持 macOS / Windows
  • 配置相对简单

实际体验：

  • 在局域网下尚可
  • 一旦画面稍微复杂（Xcode、模拟器、滚动代码）
  • 明显卡顿，输入延迟高

结论：

对开发场景并不友好，尤其是需要频繁编辑代码、切换窗口时，体验偏差。

三、方案二：向日葵

特点：

  • 国内用户非常多
  • 上手简单
  • 默认通过向日葵服务器进行中继

优点：

  • 几乎零配置
  • 外网访问很方便

不足：

  • 数据需要经过第三方服务器
  • 免费版在清晰度、流畅度上有明显限制
  • 对于长时间开发使用，体验不够稳定

结论：

临时远程、应急处理可以，但作为日常开发主力方案，有些受限。

四、方案三：RustDesk（最终选择）

RustDesk 是一个让我非常惊喜的方案。

核心特点：

  • 开源
  • 支持 自建服务器
  • 完全掌控数据
  • macOS / Windows / Linux 全平台

1. 内网体验

在局域网环境下：

  • 延迟极低
  • 画面流畅
  • 输入几乎无感

基本可以做到：

像在本地操作 Mac mini 一样使用 Xcode。

2. 外网访问

通过以下方式：

  • 自建 RustDesk Server
  • 端口映射 / 公网 IP

实现效果：

  • 外网同样可以远程
  • 延迟可接受
  • 不依赖第三方中继

3. 对开发者特别友好的点

  • 不占用显示器
  • 不需要频繁切换键盘鼠标
  • Windows 写代码，Mac 负责编译 / 运行
  • 非常适合 Mac mini + Windows 主力机 这种组合

结论：

RustDesk 是目前我体验下来，最适合“开发型远程”的方案。

五、最终方案总结

方案流畅度外网数据可控适合长期开发
RealVNC一般支持一般不推荐
向日葵一般很方便低临时使用
RustDesk很好支持高强烈推荐

六、Docker 安装 RustDesk Server

配置文件

# docker-compose.yml
networks:
  rustdesk-net:
    external: false

services:
  hbbs:
    container_name: hbbs
    ports:
      - 21115:21115
      - 21116:21116
      - 21116:21116/udp
      - 21118:21118
    image: rustdesk/rustdesk-server:latest
    command: hbbs -r kbbr.mariodingdang.xyz:21117
    volumes:
      - ./data:/root
    networks:
      - rustdesk-net
    depends_on:
      - hbbr
    restart: unless-stopped

  hbbr:
    container_name: hbbr
    ports:
      - 21117:21117
      - 21119:21119
    image: rustdesk/rustdesk-server:latest
    command: hbbr
    volumes:
      - ./data:/root
    networks:
      - rustdesk-net
    restart: unless-stopped

启动

$ docker-compose up -d

国内可能会无法拉去Docker镜像，那是另外的问题，这里就不展开了。

查看容器日志，找到key

$ docker logs hbbs

七、写在最后

对于像我这样：

  • 用 Windows 作为主力机
  • 用 Mac mini 进行 iOS 开发
  • 又不想增加额外显示器的人来说

RustDesk + Mac mini 是一套性价比极高、体验也非常顺手的方案。

如果你也在折腾 iOS 开发、WebDAV 客户端、或者类似的跨平台开发环境，希望这篇实践能对你有参考价值。
